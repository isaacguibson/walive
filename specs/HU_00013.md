# HU_00013 — Selection Tool and Pixel Content Transformation

## 1. Objective

Reimplement the Selection Tool because the previous implementation was not working correctly.

The tool must allow users to select a rectangular region of the canvas and transform the selected pixel content by:

- Moving the selected content to a new position by dragging inside the selection.
- Resizing the selected content by dragging its edges or corner handles.
- Confirming the transformation by clicking outside the selection.
- Canceling the current transformation using Escape before it is committed.

The implementation must integrate with the existing drawing canvas, layers, frames, undo/redo system, and project persistence.

The selection must operate on actual artwork pixels rather than moving only a visual selection rectangle.

## 2. Tool Availability

Restore the **Selection Tool** to the left drawing tools sidebar.

Use an appropriate selection icon and provide a tooltip and accessible label.

When selected, the tool must display its selection-specific options in the right-side Tool Options panel.

The Selection Tool must be independent of the Brush, Eraser, Fill, and Bézier Curve tools.

Switching to another tool while a transformation is pending must follow the application's established editing confirmation policy. If no policy exists, prompt the user to apply or discard the pending transformation.

## 3. Selection Creation

### 3.1 Rectangular selection

The initial implementation must support rectangular selections.

The user creates a selection by clicking and dragging across the canvas.

- The initial pointer position defines one corner.
- The current pointer position defines the opposite corner.
- The selection rectangle updates during the drag.
- The user can drag in any direction, including from bottom-right to top-left.
- The final rectangle must be normalized to positive width and height.

Display a visible selection outline over the canvas.

The outline and its handles are editor overlays and must never become part of the artwork or appear in exported images.

### 3.2 Selection validation

A selection must have a positive width and height.

If the user releases the pointer without creating a meaningful selection, discard the incomplete selection and restore the previous canvas interaction state.

The selection rectangle must respect the canvas boundaries. The user must not be able to select pixels outside the actual canvas.

The selection must remain correctly aligned with the artwork at every supported zoom level and canvas pan position.

## 4. Selected Content

### 4.1 Selection source

The selection operates on the currently active frame and currently active drawing layer.

Only the pixels belonging to the active layer and inside the selected region are transformed.

Pixels on other layers must remain unchanged.

The tool must use the existing layer model and rendering pipeline. It must not flatten the entire frame or merge multiple layers as a side effect of a selection operation.

### 4.2 Pixel extraction

After a selection is created, identify the source pixel region within the active layer.

Maintain sufficient information to restore the original pixels if the user cancels the transformation.

The selected content must be represented independently from the selection outline so that moving or resizing it does not modify the selection overlay itself.

If the selected region contains transparent pixels, preserve their transparency during movement and resizing.

If the selection contains no visible pixels, allow the selection rectangle to exist, but do not create visible artwork when it is moved or resized.

### 4.3 Preserve unselected content

When the user moves or transforms the selected content, the original pixels within the selected area must be removed from their original position in the active layer, leaving that region transparent where applicable.

Pixels outside the selected region must remain unchanged.

Do not overwrite or erase unrelated pixels outside the selection.

When the transformation is committed, render the transformed content at its destination in the active layer.

If the destination overlaps existing pixels outside the source region, apply the transformed pixels using a clearly defined compositing operation. The default behavior should be normal alpha compositing, without modifying other layers.

The implementation must avoid leaving unintended remnants at the original position.

## 5. Moving Selected Content

### 5.1 Interaction

When a selection exists, the user can move its contents by dragging inside the selection.

During the drag:

- The selected content follows the pointer.
- The selection outline follows the transformed content.
- The movement must feel responsive.
- The original source content must not be repeatedly erased or accumulated during pointer movement.

The transformation should be previewed without destructively modifying the underlying layer until it is committed.

### 5.2 Movement constraints

Allow movement in any direction.

The selected content must not be moved beyond the canvas boundaries in a way that creates invalid image coordinates.

When a movement would extend beyond the canvas, clip the rendered result to the canvas bounds.

Use the same canvas coordinate system and pan/zoom transformations as the other drawing tools.

### 5.3 Pointer behavior

A pointer press inside the selected content initiates movement.

A pointer press on a resize handle initiates resizing instead.

A pointer press outside the selection confirms the current transformation and starts a new selection only if the user continues the appropriate drag gesture. A simple click outside must confirm the transformation and finish the current selection, as defined in Section 8.

The implementation must distinguish between clicking, dragging, and releasing so that a click does not accidentally move content.

## 6. Resizing Selected Content

### 6.1 Resize handles

Display eight resize handles around the selection:

- Four corner handles.
- Four edge-center handles.

The handles must be easy to identify and interact with at different zoom levels.

Handle sizes should remain usable on screen regardless of canvas zoom.

### 6.2 Resizing behavior

Dragging a corner handle must resize the selected content along both axes.

Dragging an edge-center handle must resize the selected content along the corresponding axis while preserving the other dimension.

The selection outline and the content preview must update together during resizing.

Resizing must transform the actual selected pixel content, not merely change the outline dimensions.

### 6.3 Aspect ratio

By default, resizing is unconstrained.

Provide a Keep Aspect Ratio option in Tool Options.

When enabled, preserve the aspect ratio of the selected content during resizing.

If the existing application supports modifier-key conventions, a documented modifier may temporarily constrain the aspect ratio. Do not introduce an undocumented modifier behavior that conflicts with existing shortcuts.

### 6.4 Minimum size and invalid transformations

Prevent the selection from collapsing into invalid dimensions.

Define a minimum valid selection size based on the pixel representation.

If the user drags a handle past the opposite side, either normalize the resulting rectangle and maintain intuitive handle behavior or stop the resize at the minimum valid dimension. Choose one behavior consistently and test it.

Do not create negative dimensions, invalid pixel buffers, or corrupted layer data.

### 6.5 Pixel interpolation

Use a suitable interpolation method for resizing raster content.

Provide a Resampling option if practical:

- Nearest Neighbor: preserves hard pixel edges and is suitable for pixel art.
- Smooth: uses interpolation for smoother resizing.

Default to Smooth for general artwork unless the application has an established pixel-art-oriented default.

The selected resampling mode must be applied consistently during preview and final commit.

## 7. Transformation Preview

During movement or resizing, render a non-destructive preview of the transformed content.

The preview must:

- Follow the pointer smoothly.
- Display the transformed selection bounds.
- Preserve alpha transparency.
- Avoid modifying the source layer until commit.
- Avoid duplicating pixels on repeated pointer updates.
- Remain aligned with the canvas during zooming and panning.

The selection outline, handles, and any transformation guides must remain editor overlays.

If canvas rendering is asynchronous, ensure stale preview operations cannot overwrite the latest transformation state.

## 8. Confirming and Finishing a Selection

### 8.1 Click outside the selection

Clicking outside the active selection confirms the current transformation and finishes the selection.

The application must:

1. Apply the pending movement or resize to the active layer.
2. Record the operation in the undo history.
3. Remove the selection outline and resize handles.
4. Clear the temporary transformation state.
5. Return the canvas to its normal editing state.

A simple click outside must not begin an unintended stroke or other drawing operation.

If the user clicks outside while a transformation is pending, that click is reserved for confirming the transformation. It must not automatically create a second selection.

A subsequent drag may create a new selection.

### 8.2 No transformation performed

If the user creates a selection but does not move or resize its content, clicking outside must finish the selection without modifying the underlying pixels.

Do not create an unnecessary undo entry for an operation that did not change the artwork.

### 8.3 Empty selection

If the selection contains no visible pixels, finishing it must not create an artwork modification.

The application must still clear the selection state correctly.

## 9. Canceling a Transformation

Pressing Escape while a transformation is pending must discard the preview and restore the original layer content.

Cancellation must:

- Restore the original source pixels.
- Remove the temporary preview.
- Restore the selection or return to the appropriate previous state.
- Avoid creating an undo entry.
- Leave unrelated layers and frames unchanged.

If no transformation is pending, Escape may clear the current selection, following the application's established keyboard interaction conventions.

Closing the project or switching scenes with a pending transformation must not silently lose or partially apply artwork. Use the application's established confirmation policy.

## 10. Undo and Redo

Treat a completed selection transformation as a single undoable operation.

Examples:

- Move selected content.
- Resize selected content.
- Move and then resize before committing.

If the user moves and resizes the same selection before confirming it, the combined transformation should normally produce one undo entry.

Undo must restore the exact original artwork, including the original source pixels.

Redo must reapply the committed transformation.

Selection creation and selection outline changes alone must not create artwork undo entries.

Canceled transformations must not affect undo/redo history.

Use the existing history mechanism rather than introducing a separate, incompatible undo stack.

## 11. Layers, Frames, and Scenes

The Selection Tool must operate on the active layer of the active frame in the active scene.

It must not transform content in:

- Other layers.
- Other frames.
- Other scenes.
- Onion-skin reference frames.

Switching frames, layers, scenes, or projects while a transformation is pending must first resolve that transformation according to the established confirmation policy.

The tool must not silently apply a pending transformation to a different layer or frame.

## 12. Save, Reopen, and Export

Once committed, transformed artwork must be saved using the existing project persistence mechanism.

After saving and reopening the project, the transformed pixels must appear in the correct location and with the correct dimensions.

Exported PNG files, image sequences, GIFs, and videos must include the committed transformation but must not include selection outlines, handles, or preview overlays.

The temporary selection and transformation state does not need to persist across application restarts.

## 13. Performance and Implementation

Inspect the existing selection implementation and canvas architecture before making changes.

Do not simply re-enable the old implementation without identifying and fixing the underlying cause of its failure.

Reuse existing coordinate conversion, layer storage, canvas rendering, history, and persistence services wherever possible.

Separate the following responsibilities:

- Selection geometry and hit testing.
- Selected pixel extraction.
- Transformation state.
- Movement and resize calculations.
- Preview rendering.
- Final pixel commit.
- Undo/redo integration.

Use the existing canvas renderer and layer representation rather than introducing a separate drawing system.

For raster transformations, prefer an approach that avoids copying or reallocating the entire layer on every pointer movement.

The editor must remain responsive for selections containing large pixel regions.

Ensure pointer capture and release are handled correctly so that a drag remains active if the pointer temporarily moves outside the selection handles or canvas.

Handle high-DPI displays and different zoom levels correctly.

## 14. Testing Requirements

Implement automated tests for:

- Creating rectangular selections in every drag direction.
- Selection bounds and canvas clipping.
- Moving selected content horizontally, vertically, and diagonally.
- Resizing using each of the eight handles.
- Aspect-ratio-constrained resizing.
- Nearest-neighbor and smooth interpolation.
- Transparent pixels inside the selection.
- Empty selections.
- Preservation of pixels outside the selection.
- Preservation of other layers and frames.
- Click-outside confirmation.
- Ensuring the confirmation click does not start an unintended drawing operation.
- Escape cancellation and restoration of original pixels.
- Undo and redo of committed transformations.
- No undo entry for canceled or unchanged operations.
- Save and reopen after transformation.
- Export without editor overlays.
- Coordinate correctness under canvas pan and zoom.
- Pointer capture and release behavior.
- Switching tools, layers, frames, and scenes while a transformation is pending.
- Large selections and rendering responsiveness.

Include integration tests that reproduce the failure modes of the previous Selection Tool implementation, where those failure modes can be identified.

## 15. Acceptance Criteria

- The Selection Tool is available in the left toolbar and works reliably.
- The user can create a rectangular selection around canvas content.
- Dragging inside the selection moves the actual selected pixels.
- Dragging any edge or corner resizes the actual selected content.
- Transparency is preserved.
- Pixels outside the selection remain unchanged.
- Other layers, frames, and scenes are not modified.
- Clicking outside confirms the transformation and clears the selection.
- The confirmation click does not unintentionally draw or start a new selection.
- Escape cancels a pending transformation and restores the original pixels.
- Undo and redo correctly restore and reapply committed transformations.
- The transformed artwork persists after saving and reopening the project.
- Exported images and animations contain the transformed artwork without selection overlays.
- The editor remains responsive during selection and transformation.
- The implementation fixes the previous tool's underlying failure rather than reintroducing the same behavior.

## 16. Out of Scope

- Freeform or polygonal selections.
- Magic Wand or color-based selection.
- Multi-layer selections.
- Selection masks and feathering.
- Rotation, skew, perspective, or arbitrary affine transformations.
- Copying or cutting selected content to the system clipboard.
- Moving vector curves as vector objects; the initial implementation operates on raster pixels in the active layer.
- Advanced transform interpolation filters beyond the specified resampling options.

## 17. Implementation Notes

Prioritize correctness of pixel extraction, source restoration, preview rendering, and final commit before adding advanced selection features.

The selection rectangle is not the artwork itself. It is an editing boundary used to identify and transform pixel content.

The implementation must maintain a clear distinction between the original layer pixels, the temporary transformation preview, and the committed result.

Do not commit changes until the user confirms the transformation by clicking outside the selection. Cancellation must reliably restore the original content without leaving residual pixels or modifying undo history.
