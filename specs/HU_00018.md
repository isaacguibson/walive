# HU_00018 — Collapsible Tool Options and AI Assistant Panels

## 1. User Story

**As a** user of the drawing and animation editor,  
**I want** to minimize and restore the Tool Options and AI Assistant panels,  
**So that** I can maximize the available canvas workspace and access these panels whenever I need them, following the familiar behavior of tool windows in IDEs such as IntelliJ IDEA.

## 2. Overview

The application must support collapsible side panels for the existing **Tool Options** and **AI Assistant** sections.

The behavior should be similar to tool windows in modern IDEs:

- Each panel has a dedicated minimize button.
- When minimized, the panel disappears from its expanded position and is represented by an icon in a vertical tool-window bar on the right side of the application.
- Clicking a minimized panel's icon restores the corresponding panel.
- The canvas and remaining editor workspace automatically adapt to the available space.
- Users can switch between the Tool Options and AI Assistant panels without losing their existing state.

This feature must integrate with the existing editor layout and preserve the current drawing, animation, project, and AI conversation states.

## 3. Initial Layout and Panel Behavior

### 3.1 Expanded Panels

The Tool Options and AI Assistant panels must retain their current functionality and content when expanded.

Each panel must display a minimize control in its header, using a recognizable icon such as a panel-collapse or sidebar-collapse icon.

The control must:

- Be visually consistent with the application's existing icon buttons.
- Include an accessible tooltip, such as `Minimize Tool Options` or `Minimize AI Assistant`.
- Minimize the corresponding panel when clicked.
- Not interfere with other panel controls or the content inside the panel.

### 3.2 Right-Side Tool Window Bar

The application must provide a vertical tool-window bar on the right side of the editor.

This bar serves as the access point for minimized panels.

It must:

- Remain accessible while either or both panels are minimized.
- Display a dedicated icon for Tool Options and another for AI Assistant.
- Use vertically arranged icons with consistent spacing and alignment.
- Provide tooltips identifying each panel.
- Highlight the icon corresponding to the currently expanded panel, when applicable.
- Follow the application's existing theme, colors, borders, and icon conventions.
- Occupy as little horizontal space as reasonably possible.

The bar must remain visible when at least one supported panel is minimized. When both panels are expanded, it may remain visible if that best fits the existing editor architecture and layout conventions.

The bar must not overlap the canvas, timeline, or other interactive editor components.

### 3.3 Minimized Panels

When a user minimizes a panel:

1. The panel's expanded content area must disappear.
2. Its icon must appear in the right-side tool-window bar.
3. The canvas and other resizable panels must reclaim the released horizontal space.
4. The panel's internal state must be preserved.
5. The editor must remain fully interactive.

Minimization must affect only the panel's visibility and layout. It must not reset or recreate the panel's contents.

For Tool Options, preserve the current selected tool, brush settings, shape settings, Bézier settings, and any other tool-specific configuration.

For AI Assistant, preserve the current conversation, message history, selected provider, selected model, reasoning or effort level where supported, composer contents, and other relevant session state.

## 4. Panel Restoration

### 4.1 Restoring a Minimized Panel

When the user clicks a panel icon in the right-side tool-window bar:

- The corresponding panel must be restored to its expanded state.
- Its content and previous state must be preserved.
- The editor layout must adjust automatically.
- The canvas must resize to accommodate the restored panel.
- The restored panel must return to its previous width whenever that width is still compatible with the available window size.

The restoration operation must not reload the project, recreate the editor, clear the current selection, interrupt animation playback unnecessarily, or reset tool settings.

### 4.2 Switching Between Panels

The layout must support switching between Tool Options and AI Assistant through their respective icons.

When the user selects a panel icon:

- If the corresponding panel is minimized, it must be restored.
- If the application uses a mutually exclusive right-side panel area, the selected panel must become visible and the previously displayed panel must be minimized or hidden according to the established layout model.
- If the existing architecture supports both panels expanded simultaneously, the implementation may preserve that capability.

The implementation must establish a consistent layout model and apply it uniformly.

The application must not create duplicate panel instances or duplicate AI conversations when switching between panels.

### 4.3 Clicking the Active Panel Icon

Clicking the icon of the currently active panel should minimize that panel, provided another expanded panel does not occupy the same exclusive panel area.

If the active panel is already minimized, clicking its icon must restore it.

Repeated clicks must not produce inconsistent layout states.

## 5. Panel Width and Layout Management

The feature must integrate with the editor's existing resizable-panel system.

Requirements:

- Preserve the user's previously configured panel width when minimizing and restoring a panel.
- Reclaim the panel's horizontal space while minimized.
- Restore the panel without unnecessarily changing the widths of unrelated panels.
- Respect the application's minimum canvas and panel dimensions.
- Prevent layout overflow, horizontal clipping, and unintended overlapping.
- Adapt correctly when the application window is resized.
- Handle narrow windows gracefully.

If the available window width is insufficient to restore a panel to its previous width, the application may reduce the restored panel width to fit within the available space, subject to its minimum supported dimensions.

The implementation must not cause the canvas to become unusable when the panels are expanded.

## 6. State Management and Persistence

The application must distinguish between panel visibility state and panel content state.

### 6.1 Panel Visibility State

Track the expanded or minimized state of each supported panel.

The state should be managed by the editor's existing layout or workspace service when available.

### 6.2 Persistence

Panel visibility and width preferences should persist across editor sessions using the application's existing user-preferences or workspace-state mechanism.

At minimum, persist:

- Tool Options expanded/minimized state.
- AI Assistant expanded/minimized state.
- Previous width of each panel, where applicable.

On application startup, restore the last saved layout preferences when valid.

If stored preferences are missing, corrupted, or incompatible with the current layout, fall back to sensible default values without preventing the application from opening.

Panel visibility preferences are application UI preferences, not project drawing data. They must not be written into individual scene or frame content unless the existing architecture explicitly defines workspace layouts as project-specific.

## 7. Interaction and Accessibility

The implementation must provide:

- Tooltips for all minimize and restore icons.
- Accessible names for icon-only controls.
- Keyboard focus for panel controls and tool-window icons.
- Visible focus indicators consistent with the application.
- Predictable focus behavior when a panel is minimized.
- Consistent hover, active, and disabled states where applicable.

Minimizing the AI Assistant must not cancel a running AI request, stop streaming, or discard the current prompt.

Minimizing Tool Options must not interrupt an active canvas interaction or silently commit or discard pending artwork.

If a panel is minimized during an ongoing interaction, the existing interaction must complete or cancel according to the current editor behavior. The panel layout operation itself must not change the interaction's outcome.

## 8. Architecture and Implementation Requirements

Before implementation, inspect the existing editor layout and panel architecture.

Identify:

- How Tool Options and AI Assistant are currently rendered and managed.
- Whether the panels already have independent visibility or collapsed states.
- How panel widths and resizable boundaries are currently stored.
- How the editor manages global application preferences.
- Whether a shared panel or tool-window abstraction already exists.
- How the current layout responds to window resizing.

Reuse and extend existing components and state management where possible.

Do not introduce a separate layout system if the existing editor architecture already provides an adequate one.

Prefer a reusable panel model that can support additional tool windows in the future without requiring a redesign of the right-side tool-window bar.

Keep panel visibility state independent from panel content state. Minimizing and restoring panels must not unnecessarily unmount and recreate stateful components.

If the framework requires unmounting a panel, explicitly preserve and restore all relevant state through the existing state-management architecture.

## 9. Acceptance Criteria

### AC01 — Minimize Tool Options

**Given** Tool Options is expanded,  
**When** the user clicks its minimize button,  
**Then** the panel disappears from its expanded position, its icon becomes available in the right-side tool-window bar, and the editor reclaims the released space.

### AC02 — Minimize AI Assistant

**Given** AI Assistant is expanded,  
**When** the user clicks its minimize button,  
**Then** the panel is minimized and its icon becomes available in the right-side tool-window bar.

### AC03 — Restore Tool Options

**Given** Tool Options is minimized,  
**When** the user clicks its icon in the right-side tool-window bar,  
**Then** the panel is restored with its previous content and configuration.

### AC04 — Restore AI Assistant

**Given** AI Assistant is minimized,  
**When** the user clicks its icon in the right-side tool-window bar,  
**Then** the panel is restored with its previous conversation and configuration.

### AC05 — Reclaim Canvas Space

**Given** one or both panels are expanded,  
**When** a panel is minimized,  
**Then** the editor layout adjusts and the canvas receives the available space without overlapping other components.

### AC06 — Preserve Tool Configuration

**Given** the user has configured a tool,  
**When** Tool Options is minimized and subsequently restored,  
**Then** the selected tool and all existing tool settings remain unchanged.

### AC07 — Preserve AI Session State

**Given** an AI conversation exists,  
**When** AI Assistant is minimized and subsequently restored,  
**Then** the conversation, model selection, provider selection, composer state, and relevant session state are preserved.

### AC08 — Preserve Running AI Operations

**Given** an AI request is currently running,  
**When** AI Assistant is minimized,  
**Then** the operation continues according to the existing AI runtime behavior and can be inspected after restoring the panel.

### AC09 — Switch Between Tool Windows

**Given** both Tool Options and AI Assistant are available through the right-side tool-window bar,  
**When** the user selects either icon,  
**Then** the corresponding panel becomes accessible according to the chosen layout model without creating duplicate panel instances.

### AC10 — Preserve Panel Width

**Given** the user has resized a panel,  
**When** the user minimizes and restores it,  
**Then** the panel returns to its previous width whenever the available space permits.

### AC11 — Persist Layout Preferences

**Given** the user changes panel visibility or width,  
**When** the application is closed and reopened,  
**Then** the saved layout preferences are restored when valid.

### AC12 — Handle Window Resizing

**Given** one or both panels are expanded,  
**When** the application window is resized,  
**Then** the panels, tool-window bar, and canvas adapt without unintended overlap or unusable layout dimensions.

### AC13 — Preserve Editor Interactions

**Given** an editor interaction or pending artwork operation exists,  
**When** a panel is minimized or restored,  
**Then** the panel transition does not silently commit, discard, or otherwise modify the artwork.

### AC14 — Maintain Accessibility

**Given** the panel controls and tool-window bar are visible,  
**When** the user navigates the interface using keyboard focus or pointer interaction,  
**Then** the controls provide appropriate accessible names, tooltips, and visible focus states.

### AC15 — Maintain Existing Functionality

**Given** the panel minimization feature is implemented,  
**When** the user works with projects, scenes, frames, layers, drawing tools, animation playback, export, and AI assistance,  
**Then** existing functionality remains available and behaves as before.

## 10. Testing Requirements

Implement automated tests where supported by the current architecture, plus manual UI verification.

Test scenarios must include:

- Minimizing and restoring each panel independently.
- Switching between panels repeatedly.
- Minimizing both panels and restoring each one.
- Verifying canvas space reclamation and restoration.
- Resizing panels before minimizing and checking restored dimensions.
- Resizing the application window while panels are expanded or minimized.
- Preserving Tool Options configuration.
- Preserving AI conversation and composer state.
- Minimizing AI Assistant during a streaming response.
- Persisting and restoring panel preferences across application restarts.
- Handling missing or invalid saved layout preferences.
- Verifying keyboard navigation, tooltips, and accessible names.
- Ensuring panel transitions do not modify pending artwork or interrupt unrelated editor interactions.
- Verifying no duplicate panel instances or duplicate AI sessions are created.

## 11. Definition of Done

This user story is complete when:

1. Tool Options and AI Assistant each have a working minimize control.
2. Minimized panels are represented by icons in a vertical tool-window bar on the right side of the editor.
3. Clicking a panel icon restores the corresponding panel.
4. The editor dynamically adjusts the canvas and panel layout.
5. Panel contents and relevant state are preserved during minimization and restoration.
6. Panel width and visibility preferences persist according to the application preferences architecture.
7. The implementation reuses existing layout and state-management components wherever appropriate.
8. The new behavior does not regress drawing, animation, project management, or AI functionality.
9. Automated tests and manual verification cover the acceptance criteria.
10. The feature follows the application's existing visual design and accessibility conventions.

## 12. Out of Scope

The following are not required by this user story:

- Adding new editor panels beyond Tool Options and AI Assistant.
- Implementing arbitrary panel docking, floating windows, or drag-and-drop rearrangement.
- Changing the internal functionality of either panel.
- Introducing project-specific panel layouts.
- Redesigning the entire editor workspace.
