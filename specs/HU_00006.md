# HU_00006.md — Onion Reference and Pen Pressure Support

## 1. Overview

**ID:** HU_00006
**Title:** Onion Reference and Pen Pressure Support
**Status:** Proposed
**Priority:** High
**Type:** Feature Enhancement
**Related HUs:** HU_00001, HU_00002, HU_00003, HU_00004, HU_00005

### 1.1. Objective

Introduce two drawing and animation enhancements to improve frame-to-frame consistency and provide more natural drawing controls:

1. **Onion Reference:** Allow users to display a previous frame or a manually designated reference frame beneath the currently selected frame, making it easier to create consistent animations.
2. **Pen Pressure Support:** Allow users to enable pressure-sensitive brush sizing when drawing with a compatible graphics tablet or pressure-sensitive input device.

Both features must integrate with the existing Editor interface and preserve the current project, frame, layer, and drawing workflows.

---

## 2. Scope

### 2.1. In Scope

* Add an Onion Reference toggle button to the frame management toolbar.
* Display the previous frame as a semi-transparent reference beneath the current frame when Onion Reference is enabled.
* Allow users to designate a specific frame as the Onion Reference through its context menu.
* Visually highlight the frame designated as the reference.
* Support only one manually designated reference frame at a time.
* Hide all onion references when the Onion Reference toggle is disabled.
* Add a pressure-sensitive brush sizing toggle to the Brush Tool Options.
* Disable the brush size input while pressure-sensitive sizing is enabled.
* Read and apply supported pen pressure data during drawing.
* Provide appropriate fallback behavior for unsupported or unavailable pressure input.

### 2.2. Out of Scope

* Displaying multiple previous or future frames simultaneously.
* Configurable onion skin colors, opacity levels, or frame ranges.
* Advanced pressure curves or customizable pressure-to-size mappings.
* Pressure-sensitive opacity, color, or other brush properties.
* Automatic reference image generation.
* Changes to existing project creation, project metadata, or asset management workflows unrelated to these features.

---

# 3. Feature 1 — Onion Reference

## 3.1. Description

The Editor must provide an Onion Reference feature that allows users to view another frame as a visual guide while editing the currently selected frame.

The feature supports two reference selection modes:

1. **Automatic Reference:** The frame immediately preceding the currently selected frame is displayed as a reference.
2. **Manually Designated Reference:** A specific frame is marked by the user and remains the reference regardless of which other frame is selected.

The Onion Reference toggle controls whether any reference is displayed. When the toggle is disabled, no reference must be visible, regardless of whether a frame has been manually designated.

## 3.2. Onion Reference Toggle

Add a toggle button to the frame management toolbar in the bottom timeline area, near the existing frame management controls.

### Requirements

* The button must clearly communicate that it controls Onion Reference visibility.
* The button must have distinct enabled and disabled visual states.
* A tooltip must be displayed when the user hovers over the button.
* The toggle must be disabled by default when the application starts or a project is opened, unless a future specification explicitly introduces a persistent user preference.
* Changing the toggle state must not modify any frame content.

### Behavior When Enabled

When Onion Reference is enabled:

* If a frame has been manually designated as the reference, display that frame as the reference.
* Otherwise, display the frame immediately preceding the currently selected frame.
* Render the reference beneath the current frame's content.
* Apply reduced opacity to the reference so that the current frame remains visually distinguishable.
* Do not allow the reference rendering to interfere with drawing, erasing, filling, selection, or other editing operations on the current frame.

### Behavior When Disabled

When Onion Reference is disabled:

* Hide all onion reference content immediately.
* Do not display the automatically selected previous frame.
* Do not display a manually designated reference frame.
* Preserve any manually designated reference selection so that it can be used again when the toggle is enabled.
* Do not modify, delete, or otherwise alter any frame or layer data.

## 3.3. Automatic Reference Selection

When Onion Reference is enabled and no frame has been manually designated as the reference, the application must automatically use the frame immediately preceding the currently selected frame.

### Requirements

* The reference must update when the user selects a different frame.
* The reference must always correspond to the immediately preceding frame in the timeline's current frame order.
* If the selected frame is the first frame, no automatic reference must be displayed.
* If the selected frame is the last frame, the reference must be the frame immediately before it, not a future frame.
* The reference must update when frames are inserted, duplicated, removed, or reordered, according to the current timeline order.
* Selecting a different frame must not change the manually designated reference selection, if one exists.

The automatic reference is a visual aid only and must not become part of the selected frame's editable content.

## 3.4. Manually Designated Reference Frame

Add a new action to the context menu displayed when the user right-clicks a frame in the timeline.

### Context Menu Action

Add the following action:

**Set as Onion Reference**

The action designates the selected timeline frame as the manually chosen reference frame.

### Requirements

* The action must be available when right-clicking any valid frame.
* Selecting the action must designate that frame as the reference.
* The designated frame must receive a clearly visible highlight border in the timeline.
* The highlight must remain visible even when Onion Reference is disabled.
* The highlight must distinguish the designated reference frame from the currently selected frame.
* Selecting another frame must not remove the reference designation.
* Selecting the already designated reference frame as the reference again must not create duplicate reference assignments.

Only one frame may be manually designated as the reference at any given time.

When a new frame is designated as the reference:

* Remove the reference designation from the previously designated frame.
* Apply the reference highlight to the newly designated frame.
* Update the displayed reference immediately if Onion Reference is enabled.
* Preserve the reference designation if Onion Reference is subsequently disabled.

The application must not allow multiple frames to remain designated as the manual reference simultaneously.

### Clearing the Manual Reference

The frame context menu must also support clearing the manual reference designation.

When a frame is currently designated as the reference, its context menu action must allow the user to remove that designation. The action label should be:

**Clear Onion Reference**

After clearing the designation:

* Remove the highlight border from the previously designated frame.
* If Onion Reference is enabled, immediately fall back to automatic reference selection based on the currently selected frame.
* If Onion Reference is disabled, keep all reference content hidden.

The context menu should display the appropriate action according to whether the clicked frame is currently designated as the reference.

## 3.5. Reference Rendering Rules

The reference must be rendered as a visual overlay beneath the editable content of the currently selected frame.

### Requirements

* The reference must appear semi-transparent or visually faded.
* The current frame's content must remain visually prominent.
* The reference must align with the current frame's canvas coordinate system.
* The reference must respect the canvas viewport's zoom and pan transformations.
* The reference must not become part of the current frame's image data.
* The reference must not be editable while displayed as an onion reference.
* Drawing tools must operate exclusively on the active frame and its selected layer.
* The reference must remain visible while the user changes drawing tools or layer selections, provided Onion Reference is enabled.
* The reference must not interfere with frame selection, timeline interactions, or canvas navigation.

If the designated reference frame is also the currently selected frame, the application must not render it as an onion reference beneath itself. The frame may retain its reference highlight in the timeline, but no duplicate reference content should appear on the canvas.

## 3.6. Frame Lifecycle and Reference Integrity

The application must preserve reference integrity when timeline operations affect the designated frame.

* **Frame duplication:** Duplicating a designated reference frame must not automatically designate the duplicate as a reference.
* **Frame insertion:** Inserting frames must preserve the designation of the existing reference frame.
* **Frame removal:** If the manually designated reference frame is removed, clear the designation. If Onion Reference remains enabled, fall back to automatic reference selection.
* **Frame reordering:** The manually designated reference must remain associated with the same frame, regardless of its new timeline position.
* **Frame content changes:** Editing the designated reference frame must update its displayed reference content.
* **Project save and reopen:** Reference designation persistence must follow the project's document-state rules. If the designation is stored in project data, it must be restored consistently when the project is reopened.

The Onion Reference visibility toggle is an editor display preference and must remain separate from frame content and frame ordering.

# 4. Feature 2 — Pen Pressure Support

## 4.1. Description

When the Brush Tool is selected, the application must provide an option that allows the user to enable pressure-sensitive brush sizing using input from a compatible graphics tablet or other pressure-sensitive input device.

When pressure-sensitive sizing is enabled, the brush size must dynamically respond to the pressure applied by the user while drawing.

When pressure-sensitive sizing is disabled, the brush must continue to use the manually configured brush size, preserving the existing behavior.

## 4.2. Brush Tool Options Toggle

Add a toggle control to the Brush Tool Options panel.

The control label must be:

**Use Pen Pressure**

### Requirements

* The toggle must be visible whenever the Brush Tool is selected.
* The toggle must have distinct enabled and disabled visual states.
* A tooltip must explain that the option uses pen pressure to control brush size.
* The option must integrate with the existing Tool Options panel.
* The option must not appear as an active brush setting for tools that do not support pressure-sensitive brush sizing.
* The enabled state must be reflected consistently in the interface and drawing behavior.

## 4.3. Brush Size Input Behavior

The existing brush size input must change its behavior according to the state of the **Use Pen Pressure** toggle.

### When Disabled

* The brush size input must remain enabled.
* The user can manually configure the brush size in pixels.
* The selected size must be used as the brush's configured size during drawing.
* Existing brush sizing behavior must remain unchanged.

### When Enabled

* The brush size input must become disabled.
* Its disabled state must be visually apparent.
* The previously configured brush size must be preserved.
* The application must calculate the effective brush size dynamically using the configured brush size and the current pen pressure.
* The configured size must act as the maximum brush size for pressure-sensitive strokes.
* Disabling pressure sensitivity must restore the previously configured brush size without requiring the user to enter it again.

The configured brush size and the effective pressure-dependent brush size must be treated as separate values.

## 4.4. Pressure-Sensitive Drawing Behavior

When **Use Pen Pressure** is enabled, the application must use pressure data provided by the input device during drawing.

### Requirements

* The brush must respond dynamically to pressure changes throughout a stroke.
* Higher pressure must produce a larger brush size.
* Lower pressure must produce a smaller brush size.
* Pressure changes must be reflected during the stroke, rather than applying a single pressure value to the entire stroke.
* The configured brush size must define the maximum effective size.
* The effective size must never be zero or negative.
* The brush must respect the existing canvas zoom, pan, and coordinate transformations.
* Pressure-sensitive drawing must work with the application's existing brush rendering and stroke persistence mechanisms.
* The final stroke must preserve the pressure-dependent size variation when the frame is saved, reopened, or rendered again.

The application should normalize supported pressure input to a value in the range from `0.0` to `1.0`.

A conceptual pressure mapping is:

`effectiveBrushSize = max(configuredBrushSize × normalizedPressure, minimumBrushSize)`

Where:

* `configuredBrushSize` is the user-configured maximum brush size in pixels.
* `normalizedPressure` is the normalized pressure value provided by the input device.
* `minimumBrushSize` is a small positive value that prevents the brush size from becoming zero.

The implementation may use an appropriate minimum size and pressure response curve, provided that increasing pressure consistently increases brush size and the configured maximum size is respected.

The application must not assume that all input devices report pressure identically. Device-specific normalization or adaptation may be necessary.

## 4.5. Input Device Compatibility and Fallback Behavior

The application must support pressure input when it is available through the underlying drawing input APIs.

### Requirements

* Detect and use pressure values supplied by compatible input devices.
* Handle pointer events that expose pressure information, including supported pen input.
* Avoid assuming that mouse input provides meaningful pressure values.
* If pressure-sensitive sizing is enabled but meaningful pressure data is unavailable, use a predictable fallback rather than producing invisible or unusable strokes.
* The fallback must maintain a positive effective brush size and preserve the configured maximum size.
* The application must not crash or interrupt drawing because pressure information is missing, invalid, or unsupported.
* When switching between input devices, the application must handle changes in pressure availability safely.

For devices without usable pressure information, the application should fall back to the configured brush size for the affected stroke or input sequence. The interface must continue to reflect the user's selected pressure setting.

The implementation must avoid interpreting the default pressure value of a mouse event as a meaningful pen pressure signal.

## 4.6. Pressure Data and Stroke Persistence

Pressure-sensitive size variation is part of the resulting stroke and must remain consistent after the stroke is completed.

### Requirements

* The drawing system must capture sufficient pressure or effective-size information to reproduce the stroke accurately.
* Saving a project must preserve pressure-dependent stroke rendering.
* Reopening a project must reproduce the same stroke appearance.
* Undo and redo must correctly restore or remove pressure-sensitive strokes.
* Copying, duplicating, or otherwise reusing frame content must preserve the appearance of pressure-sensitive strokes.
* Exported images must render pressure-sensitive strokes consistently with the canvas.

The implementation may persist normalized pressure samples, effective brush-size samples, or another suitable representation, depending on the existing drawing architecture.

The chosen representation must preserve the visual result without requiring the original input device to be connected during playback, reopening, or export.

# 5. User Experience and Interaction

## 5.1. Onion Reference Interactions

The following scenarios must be supported:

1. The user selects a frame and enables Onion Reference. If no manual reference exists, the previous frame appears as a semi-transparent overlay.
2. The user selects another frame. The automatic reference updates to the frame immediately preceding the newly selected frame.
3. The user right-clicks a frame and chooses **Set as Onion Reference**. That frame receives a highlight border and becomes the displayed reference.
4. The user selects different frames. The manually designated reference remains unchanged.
5. The user disables Onion Reference. The reference disappears, but the manual designation remains highlighted in the timeline.
6. The user enables Onion Reference again. The manually designated reference becomes visible, unless it is also the active frame.
7. The user clears the manual reference. Automatic reference selection resumes when Onion Reference is enabled.
8. The user removes the designated reference frame. The designation is cleared, and automatic reference selection resumes if Onion Reference is enabled.

## 5.2. Pen Pressure Interactions

The following scenarios must be supported:

1. The user selects the Brush Tool and sees the **Use Pen Pressure** toggle in Tool Options.
2. The user disables the toggle and changes the brush size manually. The brush uses the configured size.
3. The user enables the toggle. The brush size input becomes disabled.
4. The user draws with a compatible pressure-sensitive device. The brush size changes dynamically according to the pressure applied.
5. The user disables the toggle. The brush size input becomes available again, retaining its previous configured value.
6. The user enables the toggle while using an unsupported device. Drawing remains functional and uses the documented fallback behavior.

All new buttons and controls must have clear labels, appropriate visual states, and tooltips where needed. Icon-only controls must follow the tooltip requirement established in HU_00004.

# 6. Architecture and Implementation Considerations

## 6.1. Onion Reference Architecture

Onion Reference rendering must be implemented as a visual composition layer, separate from the editable frame content.

The rendering pipeline should conceptually follow this order:

1. Render the onion reference, if enabled and available.
2. Render the active frame's editable content.
3. Render editor overlays, selections, guides, and other applicable interface elements.

The exact rendering order may be adapted to the existing canvas implementation, provided that the reference remains beneath the active frame's content and does not become editable content.

Reference selection and rendering visibility must be independent state concepts.

A conceptual state model is:

```ts
interface OnionReferenceState {
  enabled: boolean;
  designatedReferenceFrameId: string | null;
}
```

The displayed reference must be derived from this state and the current timeline selection.

* If `enabled` is `false`, no reference is displayed.
* If `enabled` is `true` and `designatedReferenceFrameId` identifies an existing frame different from the active frame, display that designated frame.
* If `enabled` is `true` and no manual reference exists, display the frame immediately preceding the active frame, if one exists.
* If the designated reference is the active frame, do not display duplicate content.

This model is conceptual. The implementation must integrate with the existing state management and frame identification mechanisms rather than creating a competing source of truth.

## 6.2. Pen Pressure Architecture

Pressure-sensitive sizing must integrate with the existing drawing input and brush rendering systems.

The implementation should conceptually separate:

* **Brush configuration:** The user-configured maximum brush size and pressure setting.
* **Input sampling:** Collection and normalization of pressure data.
* **Stroke generation:** Calculation of effective brush size throughout a stroke.
* **Stroke persistence:** Storage of sufficient data to reproduce the final stroke.
* **Rendering:** Consistent display of the resulting stroke on the canvas and in exports.

A conceptual brush configuration is:

```ts
interface BrushPressureSettings {
  usePenPressure: boolean;
  configuredSize: number;
}
```

The actual stroke representation may include pressure samples or effective-size samples, according to the existing drawing engine.

The UI must not independently implement pressure calculations if an existing shared brush or stroke service can own that logic. Pressure-sensitive behavior should be consistent across drawing, undo/redo, frame duplication, project reopening, and export.

## 6.3. Persistence Boundaries

The implementation must distinguish between document data and temporary editor state.

* The manual reference designation is associated with a frame and must follow the project's document-state and persistence rules.
* The Onion Reference visibility toggle is an editor display preference.
* Pressure-dependent stroke data is part of the drawing content and must be persisted with the relevant frame or layer.
* The **Use Pen Pressure** toggle is a brush setting. Its persistence should follow the existing brush-settings conventions; it must not be stored as part of a completed stroke's editable history unless required by the established architecture.

Any persisted data changes must remain compatible with the project's versioning and migration conventions.

# 7. Error Handling and Edge Cases

## 7.1. Onion Reference

* If no previous frame exists, automatic reference mode must not display a reference.
* If the designated reference frame is unavailable or has been removed, clear the invalid designation and safely fall back to automatic reference selection when enabled.
* If the designated reference is the active frame, do not display it as an overlay.
* If Onion Reference is disabled, no reference may be displayed under any circumstances.
* Reference rendering errors must not prevent the active frame from being edited.
* Timeline changes must not leave stale highlight borders or reference content.
* Undo/redo behavior for reference designation changes must follow the application's established history conventions. If designation changes are included in document history, undo/redo must restore them consistently.

## 7.2. Pen Pressure

* Invalid, missing, or out-of-range pressure values must be normalized or safely handled.
* Effective brush size must always remain positive.
* Pressure-sensitive drawing must not produce missing strokes when input pressure is unavailable.
* Enabling or disabling pressure sensitivity must not discard the configured brush size.
* Switching tools must not leave the brush size input in an incorrect enabled or disabled state when the Brush Tool is selected again.
* Pressure data must remain consistent when strokes are undone, redone, copied, duplicated, reopened, or exported.
* Unsupported input devices must not cause application errors.

---

# 8. Performance Requirements

* Onion Reference rendering must remain responsive when switching between frames.
* The application should reuse cached frame renderings where appropriate.
* Reference rendering must not unnecessarily duplicate or mutate the active frame's editable data.
* Enabling or disabling Onion Reference must not cause unnecessary project saves or changes to frame content.
* Pressure sampling and size calculations must be efficient enough to support smooth drawing at normal input rates.
* Pressure-sensitive rendering must minimize visible latency between pen movement and canvas updates.
* Pressure data storage must be sufficient for visual fidelity without introducing unnecessary overhead.
* Existing drawing performance must remain acceptable when pressure sensitivity is disabled.

---

# 9. Security and Data Integrity

* Both features must operate through the existing application architecture and project APIs.
* Renderer components must not gain unrestricted filesystem access.
* Frame identification and reference designation must use stable internal frame identifiers rather than relying exclusively on timeline indexes.
* Reference rendering must never modify the source image or editable content of another frame.
* Pressure-sensitive drawing must not bypass existing project persistence, validation, or undo/redo mechanisms.
* Project data must remain valid when optional reference metadata is absent in older projects.
* Any persisted schema changes must use the application's established versioning and migration strategy.

# 13. Architectural Principles

* **Visual references are not editable content:** Onion Reference must never modify the active frame's drawing data.
* **Visibility and designation are separate:** Disabling Onion Reference hides references without removing the manual designation.
* **One manual reference at a time:** Reference selection must have a single, unambiguous source of truth.
* **Pressure affects stroke generation:** Pressure-dependent sizing must be incorporated into the stroke representation, not applied only as a temporary canvas effect.
* **Backward compatibility:** Projects without reference metadata must continue to open correctly.
* **Consistent persistence:** Completed pressure-sensitive strokes must render consistently without requiring the original input device.
* **Separation of concerns:** UI components must delegate reference selection, pressure processing, and persistence to the appropriate application services.
* **Historical specification integrity:** HU_00006 extends previous requirements without modifying the historical contents of HU_00001 through HU_00005. Any future corrections or architectural changes must be documented in a new user story.
