# HU_00008.md — Brush Toggle Buttons and Pressure-Sensitive Opacity

## 1. Overview

**ID:** HU_00008
**Title:** Brush Toggle Buttons and Pressure-Sensitive Opacity
**Status:** Proposed
**Priority:** Medium
**Type:** UI Enhancement / Drawing Feature
**Related HUs:** HU_00004, HU_00006, HU_00007

### 1.1. Objective

Improve the Brush Tool Options interface by replacing the existing switches for **Use Pen Pressure** and **Stabilize Stroke** with icon-based toggle buttons, consistent with the **Onion Reference** control.

Additionally, introduce a new pressure-sensitive drawing option that uses pen pressure to control stroke opacity, allowing artists to create darker strokes with greater pressure and lighter strokes with less pressure.

---

## 2. Scope

### 2.1. In Scope

* Replace the **Use Pen Pressure** switch with an icon-based toggle button.
* Replace the **Stabilize Stroke** switch with an icon-based toggle button.
* Use recognizable icons, consistent sizing, and visual states aligned with the existing Onion Reference button.
* Add a new **Use Pen Pressure for Opacity** toggle button to the Brush Tool Options.
* Dynamically adjust stroke opacity according to pen pressure when the new option is enabled.
* Support simultaneous use of pressure-sensitive brush size and pressure-sensitive opacity.
* Preserve existing brush behavior when the corresponding options are disabled.

### 2.2. Out of Scope

* Custom pressure curves or user-configurable pressure sensitivity.
* Pressure-sensitive color selection or hue variation.
* New graphics tablet configuration screens.
* Changes to the existing stroke stabilization algorithm.
* Changes to the Onion Reference functionality.

---

# 3. Feature 1 — Convert Existing Switches to Icon-Based Toggle Buttons

## 3.1. Description

The existing **Use Pen Pressure** and **Stabilize Stroke** controls in the Brush Tool Options panel are currently implemented as switches.

Replace both switches with icon-based toggle buttons, following the same interaction and visual conventions as the existing **Onion Reference** button in the timeline toolbar.

## 3.2. Requirements

* Replace the **Use Pen Pressure** switch with a toggle button.
* Replace the **Stabilize Stroke** switch with a toggle button.
* Use an icon that clearly represents each feature.
* Match the existing Onion Reference button's general visual style, dimensions, and enabled/disabled states.
* Display a tooltip on hover explaining each button's function.
* Clearly distinguish enabled and disabled states.
* Preserve the existing functionality of both controls.
* Preserve their current state according to the application's existing brush settings behavior.
* Ensure the controls remain accessible and have descriptive accessible labels.

Suggested icon concepts:

| Feature                      | Suggested Icon Concept                                       |
| ---------------------------- | ------------------------------------------------------------ |
| Use Pen Pressure             | Pressure-sensitive pen tip or pen with variable-width stroke |
| Stabilize Stroke             | Smooth curved line or stabilized stroke                      |
| Use Pen Pressure for Opacity | Pen with a fading or gradient stroke                         |

The exact icons should be selected from the icon library already used by the application whenever suitable icons are available.

The buttons must communicate their purpose through recognizable icons, tooltips, and accessible labels rather than relying on icons alone.

---

# 4. Feature 2 — Pressure-Sensitive Stroke Opacity

## 4.1. Description

Add a new icon-based toggle button to the Brush Tool Options panel:

**Use Pen Pressure for Opacity**

When enabled, the application must use the pressure data provided by a compatible pressure-sensitive input device to control the opacity of the brush stroke.

Higher pressure must produce a more opaque, darker stroke, while lower pressure must produce a more transparent, lighter stroke.

When disabled, the brush must continue using its existing opacity behavior, independently of pen pressure.

## 4.2. User Interface

Add the new toggle button alongside the existing brush pressure and stabilization controls.

### Requirements

* Use an icon representing pressure-sensitive opacity or stroke fading.
* Follow the same visual conventions as the Onion Reference toggle button.
* Provide distinct enabled and disabled visual states.
* Display a tooltip explaining that pen pressure controls stroke opacity.
* Provide an accessible label: **Use Pen Pressure for Opacity**.
* Preserve the option's state according to the application's existing brush settings conventions.
* Keep this feature independent of the existing **Use Pen Pressure** option, which controls brush size.

## 4.3. Behavior When Enabled

When **Use Pen Pressure for Opacity** is enabled:

* The application must read pressure data from compatible input devices during drawing.
* Higher pressure must produce higher stroke opacity.
* Lower pressure must produce lower stroke opacity.
* Opacity must respond dynamically to pressure changes throughout a stroke.
* The configured brush color must remain unchanged.
* The configured brush size must remain unchanged unless the separate **Use Pen Pressure** option is enabled.
* Pressure-sensitive opacity must work together with **Stabilize Stroke**.
* The final stroke must preserve its pressure-dependent opacity variations.

The pressure-to-opacity mapping must be consistent and predictable. The implementation may use a suitable minimum opacity to ensure that low-pressure strokes remain visible, provided that increasing pressure consistently increases opacity.

## 4.4. Behavior When Disabled

When **Use Pen Pressure for Opacity** is disabled:

* Pressure must not affect stroke opacity through this feature.
* The brush must use its existing opacity behavior.
* If no separate brush opacity control exists, the default behavior must remain fully opaque, subject to existing blending and layer opacity rules.
* Pressure-sensitive brush sizing must continue to operate independently.
* Stroke stabilization must continue to operate independently.

Disabling this option must not alter previously completed strokes.

## 4.5. Pressure Mapping

The application should normalize supported pen pressure values to a range from `0.0` to `1.0`.

A conceptual mapping is:

`effectiveOpacity = minimumOpacity + normalizedPressure × (maximumOpacity - minimumOpacity)`

Where:

* `normalizedPressure` represents the normalized pressure reported by the input device.
* `minimumOpacity` is a small, non-zero opacity value that keeps low-pressure strokes visible.
* `maximumOpacity` represents the maximum opacity allowed by the existing brush and compositing settings.

The implementation may choose appropriate minimum and maximum values based on the drawing engine's opacity conventions.

The mapping must ensure that:

* Greater pressure produces greater opacity.
* Lower pressure produces lower opacity.
* Effective opacity remains within the valid range.
* Missing or invalid pressure data does not produce invisible strokes or application errors.

## 4.6. Compatibility with Other Brush Features

The new opacity feature must work independently and in combination with the existing brush options.

| Use Pen Pressure (Size) | Use Pen Pressure for Opacity | Expected Behavior                                               |
| ----------------------- | ---------------------------- | --------------------------------------------------------------- |
| Disabled                | Disabled                     | Fixed configured brush size and existing opacity behavior       |
| Enabled                 | Disabled                     | Pressure controls brush size; opacity follows existing behavior |
| Disabled                | Enabled                      | Brush size remains fixed; pressure controls opacity             |
| Enabled                 | Enabled                      | Pressure controls both brush size and opacity                   |

The **Stabilize Stroke** option must remain compatible with all four combinations.

When both pressure-sensitive options are enabled, the application must use the same underlying pressure input data where appropriate, ensuring consistent behavior throughout the stroke.

## 4.7. Unsupported Input Devices

When pressure-sensitive opacity is enabled but meaningful pressure data is unavailable:

* Drawing must remain functional.
* The application must use a predictable fallback, such as the existing brush opacity behavior.
* Missing pressure information must not cause invisible strokes.
* Mouse input must not be interpreted as meaningful pen pressure merely because an event exposes a default pressure value.
* The toggle must continue to reflect the user's selected setting.

---

# 5. Stroke Persistence and Rendering

Pressure-sensitive opacity must be part of the finalized stroke representation.

### Requirements

* Opacity variations must remain visible after the stroke is completed.
* Undo and redo must preserve the correct stroke appearance.
* Saving and reopening a project must preserve pressure-dependent opacity.
* Copying and duplicating frame content must preserve opacity variations.
* Exported images must reproduce the same opacity behavior as the canvas.
* Completed strokes must not require the original pressure-sensitive device to reproduce their appearance.

The implementation may persist normalized pressure samples, per-point opacity values, or another suitable representation supported by the existing drawing architecture.

The final rendered result must remain consistent regardless of which representation is selected.

---

# 6. Architecture and Implementation Considerations

* Reuse the existing brush settings and drawing pipeline.
* Avoid implementing pressure handling independently in each UI component.
* Keep brush size pressure and opacity pressure as independent settings.
* Reuse the same normalized pressure samples for both features where appropriate.
* Ensure stabilization does not introduce unexpected opacity fluctuations.
* Preserve the existing project format and persistence conventions, applying schema changes only if necessary.
* Maintain Electron security boundaries and the existing application architecture.
* Prefer existing icon libraries and UI components over introducing unnecessary dependencies.

# 10. Architectural Principles

* **Consistent UI:** Brush toggle buttons must follow the existing Onion Reference control conventions.
* **Independent settings:** Pressure-sensitive size and opacity must be independently configurable.
* **Shared pressure input:** Reuse pressure data where appropriate rather than introducing redundant input processing.
* **Consistent rendering:** Finalized strokes must preserve their visual appearance across editing, persistence, and export.
* **Graceful fallback:** Unsupported pressure input must never make drawing unusable.
* **Historical specification integrity:** HU_00008 extends previous requirements without modifying the historical contents of HU_00001 through HU_00007. Any future corrections or architectural changes must be documented in a new user story.
