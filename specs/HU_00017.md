# HU_00017 — Bézier Curve Rasterization, Geometric Shapes Tool, and Selection Rotation

## 1. Objective

Improve the editor's drawing and transformation workflows by implementing the following changes:

1. Change the Bézier Curve Tool so that confirming a curve converts it into normal raster artwork, equivalent to a brush stroke.
2. Replace the Bézier Curve Tool's `Size` input with a slider ranging from 1 to 500.
3. Introduce a Geometric Shapes Tool supporting squares, triangles, circles, and straight lines, with adjustable size and rotation.
4. Extend the Selection Tool to support rotation of selected artwork.

All changes must integrate with the existing editor architecture, rendering pipeline, project persistence, and undo/redo system.

Before implementation, inspect the current codebase and reuse existing tools, services, and components wherever possible. Do not duplicate functionality that is already available.

## 2. Bézier Curve Confirmation and Rasterization

### 2.1. Objective

Change the Bézier Curve Tool so that confirming a curve converts its rendered result into normal raster artwork, equivalent to a stroke drawn manually using the Brush Tool.

After confirmation, the curve must no longer be an editable Bézier object. Its resulting pixels must remain compatible with the Selection Tool and the editor's normal raster editing workflow.

### 2.2. Editing Before Confirmation

While the user is creating or editing a pending Bézier curve, the curve must remain editable using its existing anchors, control handles, and supported curve-editing interactions.

The user must be able to adjust the curve's geometry and supported brush properties before confirming it.

The curve must remain a temporary editing object until confirmation.

### 2.3. Confirmation Behavior

When the user confirms the curve:

1. Render the final curve using the selected brush type, size, color, opacity, and other applicable brush settings.
2. Rasterize the resulting stroke onto the active layer and frame.
3. Store the resulting pixels using the same underlying representation and editing mechanisms used for normal brush artwork.
4. Remove the curve's temporary editing handles, anchors, and Bézier-specific interaction state.
5. Finalize the result as a normal raster drawing operation integrated with the existing undo/redo system.

The confirmed result must not retain editable Bézier control points or require the Bézier Tool to modify its appearance.

The final rasterized artwork must be visually equivalent to the curve preview at the time of confirmation, subject to the editor's rendering capabilities.

### 2.4. Selection Tool Compatibility

After confirmation, the resulting artwork must behave like a normal brush stroke.

The user must be able to:

- Select the rasterized artwork using the Selection Tool.
- Move the selected pixels.
- Resize the selected pixels using the existing selection handles.
- Rotate the selected pixels using the rotation functionality introduced in this HU.
- Perform other transformations already supported by the Selection Tool.

The Selection Tool must operate on the rasterized result rather than attempting to select the original Bézier geometry.

The transformation must preserve transparency and must not unintentionally modify unrelated pixels, layers, frames, or scenes.

### 2.5. Rendering and Persistence

- The rasterized curve must preserve the final appearance of the preview, including supported brush texture, size, color, and opacity.
- The result must render consistently in the editor, previews, and exported images or animations.
- Saving and reopening the project must preserve the confirmed artwork.
- Temporary Bézier editing overlays must never be included in the rasterized artwork or exported output.
- The implementation must use the existing raster drawing and persistence architecture wherever possible.

### 2.6. Undo and Redo

Confirming a Bézier curve must create a coherent undoable operation.

- Undo must remove the confirmed stroke and restore the state before confirmation.
- Redo must restore the confirmed raster artwork.
- Cancelling a pending curve must not create permanent artwork.
- Subsequent selection and transformation operations must integrate with the existing undo/redo history.

### 2.7. Acceptance Criteria

- A Bézier curve remains editable while it is pending confirmation.
- Confirming the curve rasterizes it into normal artwork on the active layer and frame.
- The confirmed result no longer exposes Bézier anchors or control handles.
- The Selection Tool can select, move, resize, and rotate the resulting artwork.
- The visual appearance is preserved after rasterization.
- The result persists after saving and reopening the project.
- Undo and redo behave consistently with normal brush strokes.
- Existing Bézier preview and brush functionality remains operational.

## 3. Bézier Curve Tool Options — Size Slider

### 3.1. Requirement

Replace the existing Bézier Curve Tool's `Size` input control with a slider.

### 3.2. Behavior

- The minimum value must be `1`.
- The maximum value must be `500`.
- The selected value must be displayed numerically.
- The user must be able to adjust the value interactively.
- Changing the value must update the pending curve preview immediately.
- The selected size must be applied when the curve is rasterized.
- The size must follow the same units and rendering semantics as the existing brush size configuration.
- The slider must follow the editor's existing theme and Tool Options layout.

Values restored from previous settings or older project data must be validated and constrained to the supported range where applicable.

### 3.3. Acceptance Criteria

- The Bézier `Size` option is displayed as a slider.
- Values from `1` through `500`, inclusive, are supported.
- The current value is visible.
- Changing the slider updates the pending curve's rendered stroke.
- The selected size is applied to the confirmed raster artwork.
- Existing settings persistence behavior remains consistent.

## 4. New Geometric Shapes Tool

### 4.1. Objective

Introduce a dedicated Geometric Shapes Tool for drawing basic geometric shapes directly on the canvas.

The tool must be available in the editor's main tool palette and integrate with the existing tool registry, Tool Options panel, canvas interaction, rendering, and undo/redo systems.

### 4.2. Supported Shapes

The `Tool Options` panel must provide a shape selector with these options:

- **Square**
- **Triangle**
- **Circle**
- **Straight Line**

Each option must have a clear label and an appropriate icon when consistent with the existing tool palette.

The tool must reuse the existing drawing architecture and rendering services wherever possible.

### 4.3. Drawing Workflow

The workflow must be:

1. The user selects the Geometric Shapes Tool.
2. The user chooses a shape in `Tool Options`.
3. The user starts positioning the shape on the canvas.
4. The user adjusts the shape's size and position.
5. The user adjusts its rotation through the supported rotation control.
6. The editor displays a live preview.
7. The user confirms or cancels the pending shape.

A pending shape must remain temporary and must not become permanent project content until confirmed.

### 4.4. Shape Geometry

Each shape must have predictable and consistent geometry:

- **Square:** equal width and height.
- **Triangle:** an equilateral triangle by default.
- **Circle:** equal horizontal and vertical radii.
- **Straight Line:** a line segment with an adjustable length and rotation.

The tool must use a documented and consistent transformation origin, preferably the center of the shape and the midpoint of a straight line.

The implementation must preserve the intended proportions of each shape.

### 4.5. Tool Options

The `Tool Options` panel must provide controls for:

- Shape type.
- Shape size.
- Shape rotation.

The size control must allow the user to adjust the dimensions of the pending shape. The implementation may use a slider, numeric input, or a combination of both, following existing editor conventions.

The rotation control must allow the user to specify an angle in degrees.

The available controls must update the live preview immediately.

Changing the shape type while a shape is pending must follow a consistent interaction policy and must not silently commit or discard existing work.

### 4.6. Canvas Interaction and Coordinates

The user must be able to position the shape using the editor's existing canvas interaction conventions.

The implementation must:

- Account for canvas zoom and pan.
- Use project-space coordinates for geometry and persistence.
- Avoid using screen-space coordinates as the stored geometry.
- Keep the preview correctly aligned with the canvas.
- Prevent canvas display scaling from affecting the intended size or rotation.

If the canvas can be panned or zoomed while a shape is pending, its position and geometry must remain consistent.

### 4.7. Confirmation and Cancellation

The pending shape must be confirmed when either of the following occurs:

- The user clicks outside the pending shape or its editing area.
- The user presses `Enter`.

The pending shape must be cancelled when the user presses `Escape`.

Additional requirements:

- Clicking outside to confirm must not unintentionally start a second shape.
- Pressing `Enter` must commit the pending shape exactly once.
- Pressing `Escape` must discard the pending shape without modifying project content.
- Confirmation must create normal editable raster artwork using the application's existing drawing representation.
- Confirmed shapes must be selectable, movable, resizable, and rotatable using the Selection Tool.
- Confirmation must integrate with the existing undo/redo history.
- Tool switching must follow a clearly defined policy and must never silently commit or discard a pending shape.

### 4.8. Rendering and Persistence

- Shapes must render on the active frame and layer.
- Confirmed shapes must persist after saving and reopening the project.
- Rendering must remain consistent between the editor, previews, and exports.
- Pending-shape previews, selection handles, and rotation controls must not appear in exported output.
- The implementation must preserve existing project compatibility or provide an explicit migration if the persisted data model needs to change.

### 4.9. Acceptance Criteria

- The Geometric Shapes Tool is available in the tool palette.
- The user can choose Square, Triangle, Circle, or Straight Line.
- Size and rotation can be adjusted.
- A live preview reflects changes to shape type, size, rotation, and position.
- Clicking outside or pressing `Enter` confirms the shape.
- Pressing `Escape` cancels the shape.
- Confirmation occurs exactly once.
- Confirmed shapes are normal raster artwork.
- Confirmed shapes can be selected and transformed using the Selection Tool.
- Shapes persist and export correctly.
- Creation and supported transformations integrate with undo/redo.

## 5. Selection Tool — Rotation Support

### 5.1. Objective

Extend the existing Selection Tool to allow the user to rotate selected raster artwork.

The implementation must preserve existing selection, movement, and resizing behavior.

### 5.2. Rotation Interaction

When artwork is selected, display a rotation handle or another clear rotation control around the selection.

The user must be able to:

- Identify the rotation handle.
- Drag the handle to rotate the selection interactively.
- See a live preview during rotation.
- Confirm the rotation by releasing the pointer or following the editor's existing transformation confirmation behavior.
- Cancel the pending rotation using `Escape`.

The implementation must prevent a rotation gesture from accidentally moving or resizing the selection.

### 5.3. Rotation Origin and Angle

Rotation must occur around the center of the selection's bounding box by default.

The rotation interaction must use a consistent angle convention in degrees and correctly account for canvas zoom and pan.

The transformation must preserve the relative positions of the selected pixels around the rotation origin.

A configurable pivot point is not required by this HU.

### 5.4. Supported Content

Rotation must support raster artwork handled by the existing Selection Tool, including:

- Normal brush strokes.
- Bézier curves after they have been confirmed and rasterized.
- Geometric shapes after they have been confirmed and rasterized.

The Selection Tool must treat these elements as raster content rather than as editable Bézier curves or pending shape objects.

### 5.5. Visual and Coordinate Requirements

- Rotation must use project-space geometry.
- Canvas zoom and pan must not change the intended rotation angle.
- The preview must remain aligned with the selected content.
- Transparent pixels must remain transparent.
- Unselected artwork must remain unchanged.
- Rotation handles and selection overlays must not appear in exported output.
- The implementation must use the existing transformation and rendering architecture wherever possible.

### 5.6. History and Persistence

- A completed rotation must be recorded as an undoable operation.
- Undo must restore the pre-rotation pixels and geometry.
- Redo must reapply the rotation.
- Saving and reopening the project must preserve the rotated result.
- Cancelling a rotation must restore the original content without leaving partial changes.

### 5.7. Acceptance Criteria

- The Selection Tool displays a usable rotation handle for supported selections.
- The user can rotate selected raster artwork interactively.
- The default rotation pivot is the center of the selection.
- Movement, resizing, and rotation remain distinguishable interactions.
- Rotation works correctly at different canvas zoom levels.
- Undo, redo, cancellation, and persistence work correctly.
- Bézier-derived artwork and geometric shapes remain selectable and rotatable after confirmation.

## 6. Shared Interaction and Input Handling

The new shape tool and Selection Tool rotation must integrate with the editor's existing keyboard and pointer event handling.

Requirements:

- `Enter` confirms a pending geometric shape.
- `Escape` cancels a pending shape or rotation operation.
- Existing keyboard shortcuts must continue working outside relevant text inputs.
- Keyboard events must not accidentally confirm or cancel an operation while the user is typing.
- Pointer interactions must account for canvas zoom and pan.
- Confirmation and cancellation handlers must be idempotent to prevent duplicate operations.
- Pending operations must have explicit lifecycle states where appropriate.
- Tool switching must have deterministic behavior for pending operations.
- No pending preview may accidentally be saved as permanent artwork.

Reuse the existing input manager and event-handling architecture rather than creating a competing global keyboard or pointer system.

## 7. Architecture and Implementation Constraints

Before implementing changes, inspect:

- The existing Bézier curve model, preview renderer, and confirmation flow.
- The raster drawing representation used by the Brush Tool.
- The Selection Tool's hit-testing and pixel transformation behavior.
- The existing tool registry and Tool Options components.
- The rendering and export pipeline.
- The undo/redo and project persistence mechanisms.
- Existing geometric primitives or shape-rendering utilities, if any.

Implement the smallest coherent set of changes that meets the requirements.

The Bézier confirmation process must reuse the normal raster drawing pipeline. It must not create a special Bézier selection implementation after confirmation.

The Geometric Shapes Tool must also produce normal raster artwork when confirmed, ensuring that the Selection Tool can transform its output through the existing raster selection mechanism.

Do not duplicate selection logic, transformation logic, keyboard handling, or rendering functionality unnecessarily.

## 9. Definition of Done

HU_00017 is complete when:

- Confirming a Bézier curve converts it into normal raster artwork.
- Confirmed Bézier artwork no longer exposes editable curve control points.
- The Selection Tool can select, move, resize, and rotate confirmed Bézier artwork.
- The Bézier `Size` option is a slider ranging from 1 to 500.
- The Geometric Shapes Tool supports Square, Triangle, Circle, and Straight Line.
- Pending shapes support size and rotation adjustment, confirmation, and cancellation.
- Confirmed geometric shapes become normal raster artwork.
- The Selection Tool supports rotation of the required raster content.
- All changes integrate with existing persistence, rendering, and undo/redo systems.
- Automated tests cover the new features and relevant regressions.
- Existing editor functionality remains operational without unintended regressions.
