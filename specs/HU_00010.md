# HU_00010 — Bézier Curve Editor Tool

## 1. User Story

**As an** artist using the 2D animation editor,
**I want** to create, select, and edit Bézier curves directly on the canvas,
**So that** I can draw smooth, precise paths and apply the existing brush types to them without manually drawing every stroke.

## 2. Objective

Introduce a dedicated Bézier Curve tool that allows users to create and edit cubic Bézier paths on the project canvas.

The tool must integrate with the existing editor architecture, including the canvas coordinate system, layers, frames, undo/redo, project persistence, and the Brush Engine implemented in HU_00009.

Curves must remain editable vector objects while being edited. Their visual appearance must be rendered using the selected brush configuration or an equivalent deterministic rendering representation.

The initial implementation must use native Canvas 2D capabilities where appropriate and must not require an external vector graphics library.

## 3. Scope

### 3.1. In Scope

* Add a Bézier Curve tool to the existing drawing tools sidebar.
* Create cubic Bézier curves through interactive pointer input.
* Display anchor points and control handles while editing.
* Select and move existing curves.
* Edit anchor points and control handles.
* Add and remove anchor points.
* Support smooth and corner anchor points.
* Configure stroke color, width, opacity, and brush type.
* Integrate with the existing Brush Engine and its supported brush types.
* Support undo/redo, save/reopen, frame duplication, and export.
* Integrate with the existing layer and frame systems.
* Preserve canvas zoom and panning behavior.

### 3.2. Out of Scope

* Automatic conversion of raster drawings into Bézier paths.
* Advanced vector Boolean operations.
* SVG import/export workflows.
* Filled closed shapes and complex path filling.
* Text-on-path.
* Automatic curve animation or tweening between frames.
* A general-purpose vector illustration subsystem.
* External plugin APIs for custom curve tools.

These capabilities may be introduced in future user stories.

## 4. Tool Integration

### 4.1. Tool Selection

Add a **Bézier Curve** tool to the existing drawing tools sidebar.

The tool must have a recognizable icon consistent with the existing editor design and provide a tooltip identifying its purpose.

Selecting the tool must display its corresponding settings in the existing Tool Options panel.

Switching between the Brush, Eraser, Fill, and Bézier Curve tools must preserve their respective configuration states.

The Bézier Curve tool must not replace or modify the behavior of the existing Brush tool.

### 4.2. Tool Options

When the Bézier Curve tool is selected, Tool Options must display:

* **Brush Type:** one of the brush types implemented in HU_00009.
* **Size:** stroke width in project canvas pixels.
* **Color:** stroke color.
* **Opacity:** base stroke opacity.
* **Use Pen Pressure:** enabled only when the chosen rendering workflow supports meaningful pressure variation along the curve.
* **Use Pen Pressure for Opacity:** enabled only when the chosen rendering workflow supports meaningful pressure-dependent opacity.

Brush-specific settings must be displayed according to the selected brush type, reusing the existing Brush Engine controls where practical.

If a brush type does not support deterministic path rendering, the tool must provide a compatible fallback or clearly disable that option rather than silently producing an inconsistent result.

The curve's visual properties must be captured when the curve is created or explicitly updated. Subsequent changes to Tool Options must not unexpectedly modify existing curves.

## 5. Bézier Curve Model

### 5.1. Cubic Bézier Segments

The initial implementation must support cubic Bézier segments.

Each segment is defined by four points:

* **P0:** start anchor point.
* **P1:** first control point.
* **P2:** second control point.
* **P3:** end anchor point.

The curve is defined by:

```text
B(t) = (1 - t)^3 P0
     + 3(1 - t)^2 t P1
     + 3(1 - t) t^2 P2
     + t^3 P3

0 <= t <= 1
```

Multiple segments must be connectable through shared anchor points to form a continuous path.

The underlying geometry must be stored independently from its rendered pixels.

### 5.2. Anchor Points and Handles

Each anchor point must store:

* Position in project canvas coordinates.
* Anchor type: corner or smooth.
* Incoming control handle, when applicable.
* Outgoing control handle, when applicable.

A smooth anchor point must allow the incoming and outgoing handles to maintain a continuous tangent direction.

A corner anchor point must allow independent handle directions.

The implementation may use relative handle coordinates or absolute canvas coordinates, provided that the model remains consistent and is documented.

### 5.3. Open Paths

The initial implementation must support open paths.

Closing a path and filling its interior are out of scope for this user story.

## 6. Curve Creation Workflow

### 6.1. Starting a Curve

When the Bézier Curve tool is active:

1. The user clicks on the canvas to create the first anchor point.
2. The user clicks and drags to create subsequent anchor points and adjust their control handles.
3. Additional points extend the current path.
4. The user finishes the path using the defined completion interaction.

The interface must provide visual feedback during creation, including the current curve preview and control handles where applicable.

### 6.2. Completing a Curve

The initial implementation must support the following completion methods:

* Double-clicking to finish the path.
* Pressing Enter to finish the path.
* Pressing Escape to cancel the path being created.

The tool must not create duplicate anchor points because of the double-click completion interaction.

Escape must cancel an unfinished path without leaving partial geometry in the active layer.

Once completed, the curve must be committed as one undoable operation.

### 6.3. Empty and Degenerate Paths

The tool must prevent invalid curve objects.

A path must contain sufficient geometry to render a meaningful stroke. A click without meaningful movement must not create an unintended visible curve.

The implementation must define and consistently enforce minimum geometry requirements, including handling coincident anchor points and zero-length segments.

## 7. Curve Selection and Editing

### 7.1. Selection

The user must be able to select an existing Bézier curve by clicking near its rendered path.

The hit-testing tolerance must account for canvas zoom so that selecting curves remains practical at different zoom levels.

The selected curve must display its anchor points and control handles.

When multiple curves overlap, the selection behavior must be deterministic and consistent with the editor's existing layer and object selection conventions.

### 7.2. Moving Curves

Dragging a selected curve's path or its selection region must move the entire curve without changing its shape.

All anchor points and control handles must move together.

Moving a curve must be recorded as an undoable operation.

### 7.3. Editing Anchor Points

The user must be able to:

* Select an anchor point.
* Drag an anchor point to a new position.
* Move control handles independently when the anchor type is corner.
* Adjust both handles while preserving tangent continuity when the anchor type is smooth.
* Convert an anchor point between corner and smooth modes.
* Add an anchor point to an existing segment.
* Remove a selected anchor point when the resulting path remains valid.

Adding an anchor point to an existing curve should preserve the original curve's geometry as closely as possible. Where feasible, the implementation should split the cubic Bézier segment mathematically rather than approximating it with a new unrelated segment.

Removing an anchor point must reconnect adjacent segments in a predictable way. The resulting shape may change, but the user must be able to undo the operation.

### 7.4. Editing Overlay

Anchor points, control handles, selection outlines, and hover indicators are editing overlays.

They must not become part of the layer's artwork or appear in exported frames.

Editing overlays must remain correctly aligned with the canvas during zooming and panning.

The overlay must be hidden when the curve tool is not active, unless the existing editor has an explicit persistent object-selection mode.

## 8. Brush Engine Integration

### 8.1. Rendering Existing Brush Types

The Bézier Curve tool must reuse the Brush Engine from HU_00009 instead of implementing a separate, incompatible brush system.

The user must be able to select any compatible brush type, including:

* Basic Brush.
* Textured Pencil.
* Charcoal Brush.
* Chalk Brush.
* Particle Brush.

The final rendered appearance must be consistent with the selected brush's supported configuration.

### 8.2. Path-Based Rendering

Brush rendering along a Bézier path must be based on the path's geometry and a deterministic sampling strategy.

Sampling must account for curve length and curvature rather than relying solely on the number of pointer events received during curve creation.

For textured and particle brushes:

* Texture placement must remain stable when the curve is redrawn or the project is reopened.
* Particle placement must use deterministic randomness or an equivalent persistent representation.
* Brush spacing must not introduce unintended gaps.
* The renderer must avoid visible discontinuities between connected segments.

### 8.3. Pen Pressure

Pen pressure during the creation gesture must not automatically be interpreted as a complete pressure profile for the entire finished curve.

If pressure variation along the curve is supported, the implementation must persist a reproducible pressure profile and use it during rendering.

If pressure-profile editing is not supported in the initial implementation, the curve must use the configured brush size and opacity consistently, with pressure-dependent curve rendering disabled for this tool.

This limitation must not affect pressure-sensitive freehand drawing in the existing Brush tool.

### 8.4. Rendering and Editing Separation

The curve geometry must remain editable independently of the rendered stroke.

Changing the geometry must trigger an updated rendering of the curve.

Changing the selected curve's brush properties through an explicit editing action may regenerate its rendered appearance.

Changing Tool Options for subsequent curves must not modify previously created curves.

The application may cache the rendered result for performance, but the editable geometry and required brush configuration must remain available for reconstructing the stroke.

## 9. Persistence and Project Integration

### 9.1. Data Model

Each Bézier curve must have a stable identifier and be associated with its owning layer and frame through the existing project model.

The persisted representation must contain, at minimum:

* Curve ID.
* Anchor points and control handles.
* Anchor types.
* Open-path state.
* Brush type.
* Brush configuration snapshot.
* Stroke color, width, and opacity.
* Deterministic rendering parameters required by the selected brush.
* Any pressure profile required to reproduce the rendered result.

The implementation must follow the existing project serialization conventions and versioning strategy.

### 9.2. Save and Reopen

Saving and reopening a project must preserve:

* Curve geometry.
* Anchor and handle positions.
* Smooth and corner anchor behavior.
* Brush type and configuration.
* Rendered appearance.
* Curve-to-layer and curve-to-frame relationships.

Unknown or invalid curve data must be handled through the existing project recovery strategy without corrupting unrelated project data.

### 9.3. Undo and Redo

The following operations must support undo and redo:

* Create a curve.
* Delete a curve.
* Move a curve.
* Move an anchor point.
* Adjust a control handle.
* Add or remove an anchor point.
* Change an anchor type.
* Explicitly modify a curve's brush properties.

Dragging an anchor point or control handle must be treated as a single logical operation rather than recording every pointer movement as a separate undo entry.

### 9.4. Frame and Layer Operations

* Curves must be rendered only in their owning frame and layer.
* Duplicating a frame must preserve its curves and their properties.
* Deleting a frame or layer must follow existing editor behavior.
* Layer visibility must affect the rendered appearance of curves according to the existing layer system.
* Onion Reference imagery must remain visual-only and must not be incorporated into curve geometry.
* Moving or editing a curve must not alter curves in other frames.

### 9.5. Export

Exported frames and animations must contain the rendered curve strokes.

Exported output must not contain editing overlays, anchor points, control handles, or selection outlines.

The exported result must preserve the configured brush appearance and opacity.

The export pipeline must use the same curve geometry and brush rendering semantics as the editor's normal rendering pipeline.

## 10. Coordinate System and Input Handling

* All anchor points and control handles must use project canvas coordinates.
* Canvas zoom and panning must not alter stored curve geometry.
* Pointer coordinates must be transformed correctly from screen coordinates into project canvas coordinates.
* Existing middle-mouse canvas panning must remain functional.
* Pointer capture or an equivalent mechanism must prevent interrupted handle drags when the pointer temporarily moves outside the canvas.
* Tool switching during an unfinished curve must follow a predictable cancellation or completion policy.
* Keyboard shortcuts must not interfere with text inputs or existing editor shortcuts.

The implementation must respect the editor's existing shortcut conventions and platform-specific behavior.

## 11. Performance Requirements

* Curve previews must update interactively during creation and editing.
* Moving a control handle must not require reloading the entire project.
* Rendering should update only the affected curve and any necessary dependent caches.
* Hit testing must remain responsive when a frame contains many curves.
* Long paths with many anchor points must remain editable without excessive memory consumption.
* Temporary preview graphics and cached rendering resources must be managed and released appropriately.
* The rendering architecture must allow future optimization without changing the persisted curve model.

## 12. Error Handling and Compatibility

* Invalid anchor coordinates or malformed path data must not crash the editor.
* Curves with missing brush settings must use valid defaults or a documented fallback.
* Unknown brush types must follow the existing compatibility strategy from HU_00009.
* Failed curve creation must not leave incomplete objects in the layer.
* Canceling an operation must restore the previous valid editing state.
* Existing raster strokes and projects must remain compatible.
* Any project format migration must follow the established versioning and migration strategy.

## 14. Testing Requirements

The implementation must include automated tests for:

* Cubic Bézier geometry and segment continuity.
* Coordinate transformations under zoom and pan.
* Anchor and control handle editing.
* Smooth and corner anchor behavior.
* Segment splitting and anchor removal.
* Curve selection and hit testing.
* Brush configuration snapshots.
* Deterministic rendering of textured and particle brushes.
* Undo/redo operations.
* Save/reopen consistency.
* Frame duplication and layer isolation.
* Export output and editing-overlay exclusion.
* Invalid and malformed curve data handling.

Manual tests must cover pointer-based curve creation, handle dragging, tool switching, and compatibility with the existing drawing workflow.

## 15. Implementation Notes

* Inspect the existing editor architecture and the implementation delivered by HU_00009 before starting.
* Reuse the existing Brush Engine and project persistence mechanisms.
* Keep curve geometry separate from rasterized output.
* Avoid introducing a mandatory external vector library.
* Do not refactor unrelated editor features.
* Preserve existing tool behavior, keyboard shortcuts, and project compatibility.
* Document any changes to the project schema, renderer interfaces, or undo/redo architecture.

## 16. Definition of Done

This user story is complete when users can create, select, and edit cubic Bézier curves on the canvas, render them with compatible brushes from HU_00009, and reliably save, reopen, undo, redo, duplicate, and export them without affecting existing raster drawing workflows.
